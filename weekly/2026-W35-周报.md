## 二、本周热点趋势（从 28 个岗位数据中提炼）

### 2.1 趋势一：薪资天花板向「基础设施 + 安全」上移
- **薪资最高区间**：AI Safety 中位 $287.5K（AI Market Pulse 最高）、Agent/RAG 基础设施 $170K–$275K、FDE $300K–$600K+、LLM 微调 $195K→$245K。
- **判断**：「会调 API」的岗位（Prompt/Trainer 基础向）正在被压价，「能搭底座、能保安全、能上生产」的岗位（基础设施/安全/AgentOps/平台）在升值。这正是后端/前端工程底盘的杠杆区。
- **对转岗者的含义**：简历/作品集应突出「工程化落地」而非「模型能力」——会写 Docker/限流/可观测/评测/成本看板，比会调 Prompt 更值钱。

### 2.2 趋势二：Prompt Engineer「hype trap」反转信号（本周最重要的认知更新）
- **数据**：ML/AI Work 2026-08 评 Prompt Engineer 为「hype trap」——316 搜索/帖（过度追捧）、需求 -19% YoY、1800+ 岗位中仅 3 个 titled "Prompt Engineer"（jobsbyculture.com）。
- **含义**：纯 Prompt 岗正被 AI Engineer / LLM Engineer 吸收，「Prompt 技能是基线，不再是专长」。
- **对转岗者的含义**：不要把「会写 Prompt」当卖点，要把它当「输入-输出契约设计 + 评测 + 版本管理」的工程能力。`docs/03` 已有 L3「可版本化/可 A/B/可评测」认知，方向正确，需在简历包装时强调「Prompt 工程化」而非「Prompt 话术」。

### 2.3 趋势三：AgentOps 独立成类（SRE + Agent 特化）
- **数据**：The Hartford「Principal AI Engineer – Agent Ops / SRE」base $168,400–$220,000；Accenture AgentOps Engineer（Singapore）$107K–$109K；LinkedIn AgentOps 岗位 +280% YoY。
- **含义**：「保 Agent」从 MLOps 子集升级为独立岗位簇，核心是失败重试、checkpoint 续跑、可观测、事故响应。
- **对转岗者的含义**：SRE/运维经验在 Agent 时代是硬通货，补 Agent 侧 trace/span + checkpoint 即可。这是「Harness 主线」的直接岗位映射。

### 2.4 趋势四：合规侧时间窗（EU AI Act）
- **数据**：EU AI Act Article 50 透明度义务已于 2026-08-02 生效（「面向消费者的 AI 必须披露其为 AI」）；高风险义务经 Digital Omnibus 延迟至 2027-12（danilchenko.dev）。
- **含义**：「面向消费者的 AI 必须自披露」已是现实合规要求，催生「工程化治理」岗位（AI Governance Engineer）。
- **对转岗者的含义**：面向台湾/大陆客户的 AI 产品需关注「AI 自披露 + 数据血缘 + 模型卡」三件套，这是面向台湾客户 AI 落地的合规底线。

### 2.5 趋势五：具身智能 / 多模态爆发（薪资天花板最高）
- **数据**：多模态算法 60-150W、具身智能算法最高 200W、VLA 80-120W；AI 训练师/数据标注需求 +2250%（科锐国际《2026 人才市场洞察》、智联猎头 2026）。
- **含义**：「感知 → 理解 → 动作」闭环算法是 2026 薪资天花板最高的方向，但门槛在「领域深度」（视觉/控制）不在「工程」。
- **对转岗者的含义**：可作为「可选进阶方向」，不必作为主线；先做文本 RAG/Agent 的「工程化落地」，再考虑多模态扩展。

### 2.6 趋势六：MCP 安全岗位「供给近零」
- **数据**：MCP/Agent 协议审计师 $130K–$175K（几乎零供给，artificialintelligencemax）；MCP 三件套（servers/typescript-sdk/python-sdk）已本地 clone+test。
- **含义**：MCP 成为 Agent 与工具交互的标准化协议后，「审计 MCP server / A2A / 工具端点」成为净新岗位类别，供给近零。
- **对转岗者的含义**：MCP 深度（spec + SDK 源码）+ 后端审计经验 = 稀缺组合，门槛在「深度」不在「广度」。

## 三、岗位能力模型更新（三期沉淀的「能力雷达」）

把 28 个岗位的能力项按「工程能力杠杆」聚类，得到 5 个能力簇（适配度 5/5 的岗位全部落在前 3 簇）：

| 能力簇 | 核心技能 | 对标的 5/5 适配岗位 | 工程底盘复用度 |
|---|---|---|---|
| **保 Agent（AgentOps）** | 失败重试、checkpoint 续跑、可观测（trace/span）、成本监控、事故响应 | AgentOps、LLMOps、Agent/RAG 基础设施 | 5/5（SRE/运维/部署经验直接复用） |
| **测 Agent（AI QA）** | 评测集构建、幻觉检测、RAG 评测（recall@k/MRR/faithfulness）、Agent 行为断言、Prompt 回归 | AI QA/Eval、RAG Engineer | 5/5（后端测试经验直接复用） |
| **架 Agent（基础设施/平台）** | 向量库选型、检索链路、Agent 运行时、LLM Gateway、多租户/配额/成本分摊 | Agent/RAG 基础设施、AI 平台、AI Integration | 5/5（后端 DB/平台/API 集成经验直接复用） |
| **管 Agent（治理/红队）** | EU AI Act/NIST AI RMF/ISO 42001、模型卡、数据血缘、prompt injection、MCP 安全 | AI Governance、AI 安全红队 | 4/5（后端审计/日志/鉴权经验复用，补 AI 治理框架） |
| **写 Agent（Agent/微调）** | ReAct/Plan-Exec、工具编排、LoRA/PEFT/QLoRA、MCP 开发 | AI Agent Developer、Agentic AI Architect、LLM Fine-tuning | 4-5/5（工程底盘 + 补 LLM 侧即可） |

> **核心结论**：后端/前端工程底盘（API/鉴权/限流/异步/容器化/部署/可观测）恰好覆盖前 3 簇（保/测/架），这正是 AI 应用工程化「最稀缺」的区间。转岗策略应是「用工程能力杠杆撬动 AI 应用层」，而非「和算法岗比模型」。
