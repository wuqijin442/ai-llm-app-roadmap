# 06 · 模型微调与部署工程化

> 微调「了解流程、能跑 demo」即可；部署是工程岗的硬加分项。

## 1. 轻量化微调（LoRA / PEFT）
- **为何主流**：全量微调已淘汰；LoRA 只训少量额外参数（<1%），单张消费级 GPU（RTX 4090）即可，成本低、快、效果近全量。
- **技术栈**：Transformers + PEFT + BitsAndBytes；4/8 位量化训练降显存。
- **流程**：数据准备(JSONL) → 清洗脱敏 → 划分训练/验证 → 加载开源模型(Qwen-7B/Llama3-8B/GLM-4-9B) → 配 LoRA(rank/alpha/目标模块) → 训练监控(Loss) → 合并导出。
- **校正**：优先 7B/13B 开源模型平衡效果与显存；垂直领域（电力/医疗/法律）问答微调是简历亮点，但不必精通炼丹。

## 2. 模型部署与工程化（重点）
目标：从「能跑」到「好用、稳定、高效、可观测」。

- **格式转换**：PyTorch → ONNX → TensorRT / ONNX Runtime，提速降显存。
- **推理优化**：KV Cache、动态批处理、量化(INT4/INT8)、模型并行。
- **推理框架（2026 首选 vLLM）**：高性能、易部署、连续批处理。
- **本地/私有化部署**：
  - 本地：Ollama 一键跑 Qwen/DeepSeek（你已具备）。
  - 云 GPU：阿里云/腾讯云 A10/4090，配公网访问 + 安全防护。
  - 容器化：Docker 镜像 + Docker Compose；K8s 为加分项。
- **API 服务化**：FastAPI/Flask 封装推理接口，做限流、负载均衡、日志。
- **监控运维**：吞吐/延迟/显存监控、异常告警、模型回滚、数据安全。

## 2b. 三大推理引擎格局（2026 新增，vLLM / SGLang / TGI）

> 来源：W36 周报 P1 修订 + 第 8/9 期 LLM Inference Engineer 条目（dexity.com / KORE1 / huggingface.co/docs/text-generation-inference）。

| 引擎 | 核心特性 | Stars | 适用场景 |
|---|---|---|---|
| **vLLM** | PagedAttention + KV Cache + continuous batching + 多模型路由 | 90.7k★ | 通用 LLM serving，生态最成熟，生产首选 |
| **SGLang** | RadixAttention 前缀缓存 + 结构化输出 xgrammar + EAGLE-3 投机解码 | 34.1k★ | Agent 工作流（TTFT 降 60%），400,000+ GPU 部署 |
| **TGI** | Rust 后端 + CUDA 加速 + continuous batching + 多 GPU 并行 | 10.9k★ | HF 官方推理服务引擎，Rust 性能优势 |

- **选型决策**：
  - 通用 LLM serving → vLLM（生态最成熟）
  - Agent 工作流（前缀复用 + 结构化输出）→ SGLang（RadixAttention）
  - HF 生态 + Rust 性能 → TGI
- **内核级优化**（进阶）：TensorRT-LLM（NVIDIA 官方）/ FlashInfer / Triton / CUTLASS；投机解码（EAGLE-3 2.36x）/ 量化（NVFP4/FP8/INT8）/ PD 分离（prefill-decode disaggregation）。
- **对标仓库**：`vllm-project/vllm`（90.7k★）、`sgl-project/sglang`（34.1k★）、`huggingface/text-generation-inference`（10.9k★）（均已克隆）。
- **压测方法**：同一 LLM（qwen3-coder:30b / DeepSeek）三引擎压测 TTFT / 吞吐 / 成本 / 容错，输出四列对比报告（对齐第 9 期 LLM Inference Engineer 岗位）。

## 3. 成本意识（企业最看重的工程素养）
- 公有 API 按 token 计费：批量任务用便宜模型（DeepSeek），复杂推理才上 GPT/Claude。
- 本地部署一次性算力 vs 长期 API 费用：量大选本地，量小选 API。
- 缓存高频问答（Redis），减少重复推理。
