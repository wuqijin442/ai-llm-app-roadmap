# 00 · 开篇：为什么转岗 AI 大模型应用

> 本篇是「动机与心智模型」篇，不谈技术，先统一认知。技术细节在后续 `01~11`。

## 一、先说清楚：转的是「应用层」，不是「算法层」

很多人一听「转 AI」就怕要啃 Transformer 数学、手写反向传播、读论文。
**对 90% 的岗位来说，不需要。**

企业招的「大模型应用开发 / AI 工程师」，真实工作长这样：

- 把业务系统的数据接进向量库，做检索增强（RAG）
- 用 LangChain / 自研 harness 把模型串成能调工具、能续跑的 Agent
- 用 FastAPI 把模型包成服务，做限流、缓存、监控、部署
- 对接业务做知识库问答、智能客服、文档抽取、运维助手

你看，**这本质就是一个「会调 LLM 的后端服务」**。你作为后端 + 前端工程师，底盘已经在了。

## 二、你的三类「已有资产」（别浪费）

| 资产 | 怎么复用到大模型应用 |
|---|---|
| 后端（Java/Spring Boot） | API 设计、鉴权、异步、限流、容器化、部署——AI 应用工程化核心；迁移到 Python/FastAPI 极快 |
| 前端（Vue） | 对话 UI、流式渲染（SSE）、ECharts 可视化——很多算法同学做不出的「产品感」 |
| 本地算力（DGX + Ollama） | 已能跑 Qwen / DeepSeek / qwen3-vl，本地实验零成本，别人还在算算力账你已跑通 |

## 三、赛道为什么是现在

- 传统技术岗收缩（如英特尔大规模裁员），AI 相关岗扩招。
- 企业落地优先级（参考多份 2026 路线共识）：**RAG > Agent > 轻量微调 > 私有化部署 > 多模态**。
- 模型外面的「系统设计」（Harness）成为 2026 新拉开差距点——而这正是工程背景的人最擅长的。

## 四、转岗不一定离开本行业

储能 / EMS 行业有大量 AI 落地场景，先做本行业的作品集风险最低、收益最高：

- 电价政策知识库问答（你最懂这块，台塑等客户痛点明确）
- 设备运维工单摘要与异常归因 Agent
- 储能系统日志自然语言查询

**结论**：你不是「从零学 AI 的小白」，你是「补齐 AI 应用层、把工程底盘变现」的转岗者。后续所有内容都按这个定位设计。
